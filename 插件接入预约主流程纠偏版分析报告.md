# Cal.diy 应用市场插件接入预约主流程纠偏版分析报告

## 一、核心概念区分：主链路 vs 旁路/审计

### 1.1 主链路（Critical Path）

**定义**：预约流程中必须同步执行、失败会导致预约无法完成或数据不一致的环节。

**特征**：
- ✅ 同步执行，阻塞预约流程
- ✅ 失败会抛出异常或阻止流程继续
- ✅ 执行结果直接影响预约数据的正确性

### 1.2 旁路/审计记录（Side Channel / Audit）

**定义**：预约流程完成后异步触发、用于记录状态变更或通知外部系统的环节。

**特征**：
- ✅ 异步执行，不阻塞主流程
- ✅ 失败不影响预约的核心状态
- ✅ 可通过任务队列重试机制恢复

### 3.2 预约改期链路（关键纠偏！）

#### ⚠️ 之前的错误分析

**旧错误写法**: 改期时调用 `updateMeeting()` 更新视频会议

**正确写法**: 改期时**直接调用 `deleteMeeting()` 删除旧会议**，新会议在新预约创建时通过 `EventManager.create()` 重新创建

#### 真实调用入口

**入口文件**: `packages/trpc/server/routers/viewer/bookings/requestReschedule.handler.ts`

**调用链**:
```
requestRescheduleHandler()
    │
    ├──► 1. 将旧预约状态设为 CANCELLED
    │
    ├──► 2. 删除旧的日历事件和视频会议（主链路）
    │       │
    │       ├──► 日历插件: deleteEvent()  ◄── Promise.allSettled
    │       │
    │       └──► 视频会议插件: deleteMeeting()  ◄── 直接调用！
    │               │
    │               └──► videoClient.deleteMeeting(credential, bookingRef.uid)
    │
    ├──► 3. 发送改期请求邮件（含新时间选择链接）
    │
    └──► 4. 用户通过邮件链接选择新时间后，走预约创建流程
            │
            └──► EventManager.create() 重新创建视频会议
```

// packages/features/conferencing/lib/videoClient.ts:105-145
const updateMeeting = async (
  credential: CredentialPayload | CredentialForCalendarService,
  calEvent: CalendarEvent,
  bookingRef: PartialReference | null  // 旧的会议引用
): Promise<EventResult<VideoCallData>> => {
  const [firstVideoAdapter] = await getVideoAdapters([credential]);
  const canCallUpdateMeeting = !!(credential && bookingRef);
  
  // 有旧会议引用时调用 updateMeeting
  const updatedMeeting = canCallUpdateMeeting
    ? await firstVideoAdapter?.updateMeeting(bookingRef, calEvent).catch(async (e) => {
        // 失败时发送故障邮件
        await sendBrokenIntegrationEmail(calEvent, "video");
        log.error("updateMeeting failed", e, calEvent);
        return undefined;
      })
    : undefined;
  
  // 返回结果
  return {
    appName: credential.appName || credential.appId || "",
    type: credential.type,
    success: !!updatedMeeting,
    uid,
    updatedEvent: updatedMeeting,
    originalEvent: calEvent,
  };
};

### 5.2 主链路 vs 旁路特征对照表

| 特征 | 主链路 | 旁路 |

| **执行时机** | 同步执行，阻塞流程 | 异步执行，不阻塞流程 |

## 七、纠偏总结

### 7.1 最关键的三个纠偏点

1. **改期流程不是 updateMeeting，而是 deleteMeeting + 重新 createMeeting**

// packages/features/conferencing/lib/videoClient.ts:105-145
const updateMeeting = async (
  credential: CredentialPayload | CredentialForCalendarService,
  calEvent: CalendarEvent,
  bookingRef: PartialReference | null
): Promise<EventResult<VideoCallData>> => {
  const uid = translator.fromUUID(uuidv5(JSON.stringify(calEvent), uuidv5.URL));
  let success = true;
  
  // 1. 动态加载视频适配器
  const [firstVideoAdapter] = await getVideoAdapters([credential]);
  
  // 2. 只有同时有凭证和旧会议引用时才调用 updateMeeting
  const canCallUpdateMeeting = !!(credential && bookingRef);
  
  const updatedMeeting = canCallUpdateMeeting
    ? await firstVideoAdapter?.updateMeeting(bookingRef, calEvent).catch(async (e) => {
        // 3. 失败时发送故障邮件
        await sendBrokenIntegrationEmail(calEvent, "video");
        log.error("updateMeeting failed", e, calEvent);
        success = false;
        return undefined;
      })
    : undefined;

  // 4. 返回结果
  if (!updatedMeeting) {
    log.error(
      "updateMeeting failed",
      safeStringify({ bookingRef, canCallUpdateMeeting, calEvent, credential })
    );
    return {
      appName: credential.appName || credential.appId || "",
      type: credential.type,
      success,
      uid,
      originalEvent: calEvent,
    };
  }

  return {
    appName: credential.appName || credential.appId || "",
    type: credential.type,
    success,
    uid,
    updatedEvent: updatedMeeting,
    originalEvent: calEvent,
  };
};

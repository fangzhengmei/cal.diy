# Cal.diy 应用市场插件接入预约主流程深度分析报告

## 一、核心概念区分：主链路 vs 旁路/审计

在深入分析之前，必须明确两个关键概念的本质区别：

### 1.1 主链路（Critical Path）

**定义**：预约流程中必须同步执行、失败会导致预约无法完成或数据不一致的环节。

**特征**：
- ✅ 同步执行，阻塞预约流程
- ✅ 失败会抛出异常或阻止流程继续
- ✅ 执行结果直接影响预约数据的正确性
- ❌ 无法通过重试或后台任务修复

### 1.2 旁路/审计记录（Side Channel / Audit）

**定义**：预约流程完成后异步触发、用于记录状态变更或通知外部系统的环节。

**特征**：
- ✅ 异步执行，不阻塞主流程
- ✅ 失败不影响预约的核心状态
- ✅ 可通过任务队列重试机制恢复
- ✅ 通常有 feature flag 控制是否启用

```typescript
export const getVideoAdapters = async (
  withCredentials: CredentialPayload[]
): Promise<VideoApiAdapter[]> => {
  const videoAdapters: VideoApiAdapter[] = [];

  for (const cred of withCredentials) {
    // 1. 将凭证类型转换为插件名称
    // zoom_video → zoomvideo
    const appName = cred.type.split("_").join("");
    
    // 2. 从映射表查找适配器（自动生成）
    let videoAdapterImport = VideoApiAdapterMap[appName as keyof typeof VideoApiAdapterMap];
    
    // 3. 降级处理：尝试去除后缀
    // zoom_video → zoom
    if (!videoAdapterImport) {
      const appTypeVariant = cred.type.substring(0, cred.type.lastIndexOf("_"));
      videoAdapterImport = VideoApiAdapterMap[appTypeVariant as keyof typeof VideoApiAdapterMap];
    }

    if (!videoAdapterImport) {
      log.error(`Couldn't get adapter for ${appName}`);
      continue;
    }

    // 4. 动态导入适配器模块
    const videoAdapterModule = await videoAdapterImport;
    const makeVideoApiAdapter = videoAdapterModule.default as VideoApiAdapterFactory;

    // 5. 创建适配器实例，传入用户凭证
    if (makeVideoApiAdapter) {
      const videoAdapter = makeVideoApiAdapter(cred);
      videoAdapters.push(videoAdapter);
    }
  }

  return videoAdapters;
};
```

### 3.2 配置读取工具函数

**文件位置**: `packages/app-store/_utils/getEventTypeAppData.ts`

```typescript
export const getEventTypeAppData = <T extends EventTypeAppsList>(
  eventType: BookerEventForAppData,
  appId: T,
  forcedGet?: boolean  // 是否强制获取（忽略 enabled 标志）
): EventTypeApps[T] | null => {
  const metadata = eventType.metadata;
  const appMetadata = metadata?.apps && metadata.apps[appId];
  
  if (appMetadata) {
    const app = appMetadata as CommonAppData;
    // 关键：只有 enabled=true 才返回配置
    const allowDataGet = forcedGet ? true : app.enabled;
    
    return allowDataGet
      ? {
          ...appMetadata,
          // 优先级：eventType.price > appMetadata.price
          price: eventType.price || app.price || null,
          currency: eventType.currency || app.currency || null,
          // 字段兼容
          TRACKING_ID: app.TRACKING_ID || app.trackingId || null,
          TRACKING_EVENT: app.trackingEvent || "Lead",
        }
      : null;
  }

  // 向后兼容：旧版本的存储方式
  const legacyAppsData = {
    stripe: {
      enabled: !!eventType.price,    // 旧版本：有 price 即表示启用
      price: eventType.price,
      currency: eventType.currency,
      paymentOption: "ON_BOOKING",
    },
    giphy: {
      enabled: !!eventType.metadata?.giphyThankYouPage,
      thankYouPage: eventType.metadata?.giphyThankYouPage || "",
    },
  } as const;

  const legacyAppData = legacyAppsData[appId as Extract<T, keyof typeof legacyAppsData>];
  const allowDataGet = forcedGet ? true : legacyAppData?.enabled;
  return allowDataGet ? legacyAppData : null;
};
```

### 3.3 配置优先级规则

| 配置项 | 优先级 1（最高） | 优先级 2 | 优先级 3（最低） |
|--------|------------------|----------|------------------|
| 价格 | `eventType.price` (DB 字段) | `metadata.apps.stripe.price` | `null` |
| 货币 | `eventType.currency` (DB 字段) | `metadata.apps.stripe.currency` | `null` |
| 追踪 ID | `metadata.apps.ga4.TRACKING_ID` | `metadata.apps.ga4.trackingId` | `null` |

### 4.2 支付插件（Stripe）主链路介入

#### 介入时机：预约创建时

支付插件是**最前置**的主链路介入点，在预约数据持久化之前就必须完成。

**关键代码**：`packages/app-store/_utils/payments/handlePaymentSuccess.ts`

```typescript
export async function handlePaymentSuccess(params: {
  paymentId: number;
  appSlug: string;
  bookingId: number;
  traceContext: TraceContext;
}) {
  const { paymentId, bookingId, appSlug, traceContext } = params;
  
  // 1. 获取预约详情和相关数据
  const { booking, user: userWithCredentials, evt, eventType } = await getBooking(bookingId);
  
  // 2. 取消待发送的"等待支付"邮件
  await tasker.cancelWithReference(booking.uid, "sendAwaitingPaymentEmail");

  // 3. 准备预约更新数据
  const bookingData: Prisma.BookingUpdateInput = {
    paid: true,                    // 标记为已支付
    status: BookingStatus.ACCEPTED, // 状态改为已接受
  };

  // 4. 获取用户所有凭证（日历 + 视频会议）
  const allCredentials = await getAllCredentialsIncludeServiceAccountKey(
    userWithCredentials,
    { ...booking.eventType, metadata: booking.eventType?.metadata as EventTypeMetadata }
  );

  const isConfirmed = booking.status === BookingStatus.ACCEPTED;

  // 5. 如果预约已确认，执行 EventManager.create()
  if (isConfirmed) {
    const apps = eventTypeAppMetadataOptionalSchema.parse(eventType?.metadata?.apps);
    
    // ╔════════════════════════════════════════════════════════════╗
    // ║  主链路关键点：EventManager 协调所有日历和视频插件          ║
    // ╚════════════════════════════════════════════════════════════╝
    const eventManager = new EventManager(
      { ...userWithCredentials, credentials: allCredentials },
      apps
    );
    
    const scheduleResult = areCalendarEventsEnabled
      ? await eventManager.create(evt)  // 同步执行！阻塞流程
      : placeholderCreatedEvent;
    
    bookingData.references = { create: scheduleResult.referencesToCreate };
  }

  // 6. 检查是否需要组织者确认
  const requiresConfirmation = doesBookingRequireConfirmation({ booking: { ...booking, eventType } });
  if (requiresConfirmation) {
    delete bookingData.status;  // 不自动确认
  }

  // 7. 事务更新：支付记录 + 预约状态
  const paymentUpdate = prisma.payment.update({
    where: { id: paymentId },
    data: { success: true },
    select: { id: true, externalId: true },
  });

  const bookingUpdate = prisma.booking.update({
    where: { id: booking.id },
    data: bookingData,
    select: { status: true },
  });

  const [payment, updatedBooking] = await prisma.$transaction([paymentUpdate, bookingUpdate]);

  // 8. 触发 BOOKING_PAID webhook（注意：这是旁路！）
  try {
    const subscriberMeetingPaid = await getWebhooks({
      userId, eventTypeId: booking.eventTypeId,
      triggerEvent: WebhookTriggerEvents.BOOKING_PAID,
      teamId: booking.eventType?.teamId,
    });

    const bookingPaidSubscribers = subscriberMeetingPaid.map((sub) =>
      sendPayload(/* ... */).catch((e) => {
        // 关键：webhook 失败不抛出异常！
        tracingLogger.error("Error executing webhook...", safeStringify(e));
      })
    );
    await Promise.all(bookingPaidSubscribers);
  } catch (error) {
    log.error("Error while triggering BOOKING_PAID webhook", safeStringify(error));
    // 继续执行，不影响主流程
  }

  // 9. 后续处理：确认或请求确认
  if (!isConfirmed) {
    if (!requiresConfirmation) {
      // ╔═══════════════════════════════════════════════════════════╗
      // ║  再次调用 EventManager（在 handleConfirmation 内部）        ║
      // ╚═══════════════════════════════════════════════════════════╝
      await handleConfirmation({
        user: { ...userWithCredentials, credentials: allCredentials },
        evt, prisma, bookingId: booking.id, booking,
        paid: true, platformClientParams, traceContext: updatedTraceContext,
      });
    } else {
      await handleBookingRequested({ evt, booking });
    }
  } else if (areEmailsEnabled) {
    // 10. 发送确认邮件
    await sendScheduledEmailsAndSMS({ ...evt }, undefined, undefined, undefined, eventType.metadata);
  }

  throw new HttpCode({
    statusCode: 200,
    message: `Booking with id '${booking.id}' was paid and confirmed.`,
  });
}
```

### 4.3 视频会议插件主链路介入

#### 介入时机：EventManager.create/update/delete 时

视频会议插件通过 `EventManager` 协调，在预约创建、修改、取消时同步执行。

**核心调用链**：

```
handleConfirmation()
    │
    ▼
EventManager.create(evt)
    │
    ├──► 日历服务: createEvent()  ◄── 主链路
    │
    └──► 视频客户端: createMeeting()  ◄── 主链路
              │
              ├──► getVideoAdapters(credentials)
              │
              └──► 具体插件 VideoApiAdapter.createMeeting()
                       │
                       ├──► Zoom: POST /users/me/meetings
                       ├──► Google Meet: 调用 Calendar API
                       └──► ...
```

**关键代码**：`packages/features/conferencing/lib/videoClient.ts`

```typescript
const createMeeting = async (
  credential: CredentialPayload | CredentialForCalendarService,
  calEvent: CalendarEvent
) => {
  const uid: string = getUid(calEvent.uid);
  
  // ╔══════════════════════════════════════════════════════════╗
  // ║  主链路关键点 1：验证应用是否启用                           ║
  // ╚══════════════════════════════════════════════════════════╝
  if (!credential || !credential.appId) {
    throw new Error("Credentials must be set!");
  }

  const enabledApp = await prisma.app.findUnique({
    where: { slug: credential.appId },
    select: { enabled: true },
  });

  if (!enabledApp?.enabled) {
    throw `Location app ${credential.appId} is either disabled or not seeded at all`;
  }

  // ╔══════════════════════════════════════════════════════════╗
  // ║  主链路关键点 2：动态加载适配器并创建会议                   ║
  // ╚══════════════════════════════════════════════════════════╝
  const videoAdapters = await getVideoAdapters([credential]);
  const [firstVideoAdapter] = videoAdapters;

  try {
    // 同步调用插件的 createMeeting 方法
    const createdMeeting = await firstVideoAdapter?.createMeeting(calEvent);
    
    return {
      ...returnObject,
      createdEvent: createdMeeting,
      success: true,
    };
  } catch (err) {
    // ╔══════════════════════════════════════════════════════════╗
    // ║  主链路关键点 3：失败降级机制                               ║
    // ║  视频会议创建失败时，不会让整个预约失败，而是：            ║
    // ║  1. 发送故障通知邮件给组织者                                ║
    // ║  2. 降级使用 Cal Video (Daily.co)                          ║
    // ╚══════════════════════════════════════════════════════════╝
    
    await sendBrokenIntegrationEmail(calEvent, "video");
    log.error("createMeeting failed", safeStringify(err), ...);
    
    // 降级到 Cal Video
    const defaultMeeting = await createMeetingWithCalVideo(calEvent);
    if (defaultMeeting) {
      calEvent.location = DailyLocationType;  // 修改位置类型
    }

    return { ...returnObject, originalEvent: calEvent, createdEvent: defaultMeeting };
  }
};
```

export const confirmHandler = async ({ ctx, input }: ConfirmOptions) => {
  const { bookingId, confirmed } = input;
  
  // 1. 获取预约详情
  const booking = await prisma.booking.findUniqueOrThrow({
    where: { id: bookingId },
    select: { /* ... 所有关联数据 ... */ },
  });

  // 2. 权限检查
  const bookingAccessService = new BookingAccessService(prisma);
  const isUserAuthorizedToConfirmBooking = await bookingAccessService.doesUserIdHaveAccessToBooking({
    userId: ctx.user.id,
    bookingId: bookingId,
  });

  if (!isUserAuthorizedToConfirmBooking) {
    throw new TRPCError({ code: "UNAUTHORIZED", message: "User is not authorized" });
  }

  // 3. 检查是否已确认
  if (booking.status === BookingStatus.ACCEPTED) {
    throw new TRPCError({ code: "BAD_REQUEST", message: "Booking already confirmed" });
  }

  // 4. 检查支付状态
  if (confirmed && booking.payment.length > 0 && !booking.paid) {
    // 未支付但需要确认的情况处理
    await prisma.booking.update({
      where: { id: bookingId },
      data: { status: BookingStatus.ACCEPTED },
    });
    return { message: "Booking confirmed", status: BookingStatus.ACCEPTED };
  }

  // 5. 构建 CalendarEvent 对象
  const evt: CalendarEvent = {
    type: booking?.eventType?.slug as string,
    title: booking.title,
    // ... 所有预约详情
    location: booking.location ?? "",
    uid: booking.uid,
  };

  if (confirmed) {
    // ╔══════════════════════════════════════════════════════════╗
    // ║  主链路关键点：获取凭证并调用 handleConfirmation           ║
    // ╚══════════════════════════════════════════════════════════╝
    
    // 5.1 获取用户所有凭证（日历 + 视频会议）
    const credentials = await getUsersCredentialsIncludeServiceAccountKey(user);
    const userWithCredentials = { ...user, credentials };
    const allCredentials = await getAllCredentialsIncludeServiceAccountKey(
      userWithCredentials,
      { ...booking.eventType, metadata: booking.eventType?.metadata as EventTypeMetadata }
    );
    
    // 5.2 获取会议凭证 ID
    const conferenceCredentialId = getLocationValueForDB(
      booking.location ?? "",
      (booking.eventType?.locations as LocationObject[]) || []
    );
    evt.conferenceCredentialId = conferenceCredentialId.conferenceCredentialId;

    // 5.3 ════════════════════════════════════════════════════════
    //     主链路核心：handleConfirmation 内部调用 EventManager
    // ════════════════════════════════════════════════════════════
    await handleConfirmation({
      user: { ...user, credentials: allCredentials },
      evt,
      recurringEventId,
      prisma,
      bookingId,
      booking,
      emailsEnabled,
      platformClientParams,
      traceContext,
    });
  } else {
    // 拒绝预约的情况（旁路处理为主）
    evt.rejectionReason = rejectionReason;
    
    // 处理退款（如果有支付）
    if (booking.payment.length) {
      await processPaymentRefund({
        booking: booking,
        teamId: booking.eventType?.teamId,
      });
    }
    
    // 更新预约状态
    await prisma.booking.update({
      where: { id: bookingId },
      data: { status: BookingStatus.REJECTED, rejectionReason },
    });
    
    // 发送拒绝邮件
    if (emailsEnabled) {
      await sendDeclinedEmailsAndSMS(evt, booking.eventType?.metadata as EventTypeMetadata);
    }
    
    // 触发 webhook（旁路）
    await handleWebhookTrigger({
      subscriberOptions: { /* ... */ },
      eventTrigger: WebhookTriggerEvents.BOOKING_REJECTED,
      webhookData: { /* ... */ },
      traceContext,
    });
  }

  const message = confirmed ? "Booking confirmed" : "Booking rejected";
  const status = confirmed ? BookingStatus.ACCEPTED : BookingStatus.REJECTED;
  return { message, status };
};

export class BookingAuditTaskConsumer {
  private readonly actionServiceRegistry: BookingAuditActionServiceRegistry;
  private readonly bookingAuditRepository: IBookingAuditRepository;
  private readonly featuresRepository: IFeaturesRepository;

  // ╔══════════════════════════════════════════════════════════╗
  // ║  旁路关键点 1：Feature Flag 检查                          ║
  // ║  如果组织没有启用 booking-audit 功能，直接跳过            ║
  // ╚══════════════════════════════════════════════════════════╝
  private async shouldProcessAudit(params: {
    organizationId: number | null;
    action: BookingAuditAction;
    bookingUids: string[];
  }): Promise<boolean> {
    const { organizationId, action, bookingUids } = params;

    // 关键 1：非组织预约直接跳过
    if (organizationId === null) {
      logger.debug(
        `Skipping audit for non-organization booking: action=${action}, bookingUids=${bookingUids.join(",")}`
      );
      return false;
    }

    // 关键 2：检查 Feature Flag
    const isFeatureEnabled = await this.featuresRepository.checkIfTeamHasFeature(
      organizationId,
      "booking-audit"  // Feature Flag 名称
    );

    if (!isFeatureEnabled) {
      logger.debug(
        `booking-audit feature is disabled for organization: action=${action}, bookingUids=${bookingUids.join(",")}, organizationId=${organizationId}`
      );
      return false;
    }

    return true;
  }

  // 处理单个审计任务
  async processAuditTask(payload: SingleBookingAuditTaskConsumerPayload, taskId: string): Promise<void> {
    const { action, bookingUid, actor, organizationId, data, timestamp, source, operationId, context } = payload;

    // ════════════════════════════════════════════════════════════
    // 旁路关键点 2：先检查是否应该处理，不满足条件直接返回
    // ════════════════════════════════════════════════════════════
    if (
      !(await this.shouldProcessAudit({
        organizationId,
        action,
        bookingUids: [bookingUid],
      }))
    ) {
      return;  // 直接返回，不做任何处理
    }

    // 数据迁移（如果需要）
    const dataInLatestFormat = await this.migrateIfNeeded({ action, data, payload, taskId });

    // 创建审计记录
    await this.onBookingAction({
      bookingUid,
      actor,
      action,
      source,
      operationId,
      data: dataInLatestFormat,
      timestamp,
      context,
    });
  }

  // 创建审计记录
  private async createAuditRecord(input: CreateBookingAuditInput): Promise<BookingAudit> {
    logger.info(
      "Creating audit record",
      safeStringify({

        actorId: input.actorId,
        type: input.type,
        action: input.action,
        source: input.source,
        timestamp: input.timestamp,
        context: input.context,
      })
    );

      bookingUid: input.bookingUid,
      actorId: input.actorId,
      type: input.type,
      action: input.action,
      source: input.source,
      timestamp: input.timestamp,
      operationId: input.operationId,
      data: input.data ?? null,

    });
  }

### 7.2 OAuth Token 自动刷新

#### Zoom 适配器中的 Token 管理

**文件位置**: `packages/app-store/zoomvideo/lib/VideoApiAdapter.ts`

```typescript
const fetchZoomApi = async (endpoint: string, options?: RequestInit) => {
  const auth = new OAuthManager({
    credentialSyncVariables: { /* ... */ },
    resourceOwner: { type: "user", id: credential.userId },
    appSlug: metadata.slug,
    currentTokenObject: tokenResponse,
    
    // ╔══════════════════════════════════════════════════════════╗
    // ║  Token 刷新策略                                           ║
    // ╚══════════════════════════════════════════════════════════╝
    
    // 1. 定义如何刷新 Token
    fetchNewTokenObject: async ({ refreshToken }) => {
      if (!refreshToken) return null;
      
      const clientCredentials = await getZoomAppKeys();
      const { client_id, client_secret } = clientCredentials;
      const authHeader = `Basic ${Buffer.from(`${client_id}:${client_secret}`).toString("base64")}`;
      
      // 调用 Zoom OAuth API 刷新 Token
      return fetch("https://zoom.us/oauth/token", {
        method: "POST",
        headers: {
          Authorization: authHeader,
          "Content-Type": "application/x-www-form-urlencoded",
        },
        body: new URLSearchParams({
          grant_type: "refresh_token",
          refresh_token: refreshToken,
        }),
      }).then((response) => response.json());
    },
    
    // 2. 定义如何检查 Token 是否失效
    isAccessTokenUnusable: async function (response) {
      const responseBody = await response.json();
      // Zoom 错误码 124 表示 Token 失效
      if (responseBody.code === 124) {
        return { reason: responseBody.message ?? "" };
      }
      return null;
    },
    
    // 3. 定义如何更新数据库中的 Token
    updateTokenObject: async (newTokenObject) => {
      await prisma.credential.update({
        where: { id: credential.id },
        data: { key: newTokenObject as Prisma.InputJsonValue },
      });
    },
  });

  const { json } = await auth.request({
    url: `https://api.zoom.us/v2/${endpoint}`,
    options,
  });
  return json;
};
```

## 八、总结与对比

### 8.1 主链路 vs 旁路 核心对比表

| 维度 | 主链路（Critical Path） | 旁路/审计（Side Channel） |
|------|------------------------|---------------------------|
| **执行时机** | 同步执行，阻塞预约流程 | 异步执行，不阻塞主流程 |
| **失败影响** | 失败会导致预约失败或数据不一致 | 失败不影响预约核心状态 |
| **重试机制** | 无（失败即失败，除非有降级） | 有（任务队列支持重试） |
| **Feature Flag** | 不依赖（除非完全禁用插件） | 依赖（如 `booking-audit`） |
| **核心目的** | 完成预约的核心业务逻辑 | 记录状态变更、通知外部系统 |
| **数据一致性** | 必须强一致 | 最终一致即可 |

### 8.2 插件类型与介入方式对比表

| 插件类型 | 示例 | 介入时机 | 是否主链路 | 关键代码位置 |
|----------|------|----------|------------|--------------|
| **支付插件** | Stripe | 预约创建前 | ✅ 是 | `packages/app-store/_utils/payments/handlePaymentSuccess.ts` |
| **视频会议插件** | Zoom, Google Meet, Teams | EventManager.create/update/delete | ✅ 是 | `packages/features/conferencing/lib/videoClient.ts` |
| **日历插件** | Google Calendar, Outlook | EventManager.create/update/delete | ✅ 是 | `packages/lib/CalendarService.ts` |
| **Webhook 通知** | Zapier, Make, Custom Webhooks | 主流程完成后 | ❌ 否 | `packages/features/tasker/tasks/sendWebook.ts` |
| **CRM 集成** | HubSpot, Close.com, Salesforce | 主流程完成后 | ❌ 否 | `packages/features/tasker/tasks/crm/createCRMEvent.ts` |
| **Booking Audit** | 内部审计系统 | 主流程完成后 | ❌ 否 | `packages/features/booking-audit/` |
| **分析追踪** | GA4, PostHog, Segment | 预约成功页面 | ❌ 否 | 前端脚本注入 |

## 九、架构设计亮点

### 9.1 关注点分离

系统采用清晰的关注点分离架构：

```
┌─────────────────────────────────────────────────────────────────────────────────────┐
│                              架构分层示意                                              │
├─────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                     │
│  ┌─────────────────────────────────────────────────────────────────────────────┐   │
│  │  第 1 层：核心业务层（主链路）                                                 │   │
│  ├─────────────────────────────────────────────────────────────────────────────┤   │
│  │  - 必须完成，否则预约无效                                                      │   │
│  │  - 支付插件：必须收款成功才能创建预约                                          │   │
│  │  - 视频会议：必须生成会议链接才能发送确认邮件                                  │   │
│  │  - 日历同步：必须创建日历事件才能让组织者看到预约                              │   │
│  │                                                                              │   │
│  │  设计原则：                                                                  │   │
│  │  - 同步执行，失败抛出异常                                                    │   │
│  │  - 有降级机制但不依赖                                                        │   │
│  │  - 事务保证数据一致性                                                        │   │
│  └─────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                     │
│  ┌─────────────────────────────────────────────────────────────────────────────┐   │
│  │  第 2 层：通知层（旁路）                                                       │   │
│  ├─────────────────────────────────────────────────────────────────────────────┤   │
│  │  - 可选完成，不影响预约核心状态                                                │   │
│  │  - Webhook：通知外部系统预约状态变更                                          │   │
│  │  - CRM 集成：同步到客户关系管理系统                                          │   │
│  │  - 邮件通知：虽然是同步发送，但失败不影响核心                                  │   │
│  │                                                                              │   │
│  │  设计原则：                                                                  │   │
│  │  - 异步执行，通过任务队列                                                    │   │
│  │  - 失败可重试，不抛出异常                                                    │   │
│  │  - 有 Feature Flag 控制是否启用                                              │   │
│  └─────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                     │
│  ┌─────────────────────────────────────────────────────────────────────────────┐   │
│  │  第 3 层：审计层（纯旁路）                                                     │   │
│  ├─────────────────────────────────────────────────────────────────────────────┤   │
│  │  - 只记录，不执行任何业务逻辑                                                  │   │
│  │  - Booking Audit：记录预约状态变更历史                                       │   │
│  │  - 用于合规、回溯、报表                                                        │   │
│  │                                                                              │   │
│  │  设计原则：                                                                  │   │
│  │  - 完全异步，不影响主流程                                                    │   │
│  │  - 有严格的 Feature Flag 控制                                               │   │
│  │  - 失败可以忽略（只影响审计数据，不影响业务）                                 │   │
│  └─────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                     │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

#### OAuth Token 自动刷新

系统设计了完善的 Token 生命周期管理：

```
1. 发起 API 请求
         │
         ▼
2. 使用 Access Token 调用
         │
         ├───────────────┐
         │ Token 有效    │ Token 失效
         ▼               ▼
3. 返回结果        4. 使用 Refresh Token 刷新
                         │
                         ├───────────────┐
                         │ 刷新成功      │ 刷新失败
                         ▼               ▼
                    5. 更新数据库   6. 标记凭证失效
                       Token         通知用户重新授权
                         │
                         ▼
                    7. 使用新 Token
                       重试请求
```
